# Internal accepted-result storage and accounting

Implements ADR-SAAS-005: original signed candidate evidence plus a separate version-2 receipt signed by source and independent tenant-scoped dedupe/qualification authorities. All signing registries default empty. No source, signer, R2 client, worker, HTTP intake, export or payment is activated.

The exact schema binds candidate event/digest, workspace/job/operation/provider/request/source/policy and the fixed isolated registry namespace. Committed canonical R2/phone contract claims require independent configured signatures; shared signing secrets fail closed. Unknown fields, unsupported versions/namespaces/pending registry state, missing or wrong record/fingerprint sets, forged/altered/oversized/deep evidence and expired candidates are denied. These tests prove the application contract, not real signer behavior or R2 integration.

A current owner/admin can finalize only a single-source, entire bounded 1–25-row batch matching the existing candidate ledger. Current source switches/rights/fingerprint, membership, active entitlement and settled plus reserved caps are rechecked. Actual rows, protected receipt, workspace-unique token backstop, usage settlement and completed job/attempt/outbox commit once. Requested limits are not achieved counts. Duplicate/conflicting replays, later-job fingerprint reuse, partial writes and v1/v2 terminalization races cannot double store, charge or replace results. Old version-1 receipts still settle zero leads. Multi-source/multi-batch intake remains unavailable.

Stored rows retain allowed fields, field-to-record lineage, observed time, country/category, purpose, retention version and per-record source deadline. Existing search `name` maps to `business_name`; `address` now has an explicit allowed payload field. No raw candidate/receipt bodies or signatures enter receipts/logs/control-plane memory. Data classification and before-production encryption/deletion/backup gates are recorded as DATA-007. Payload cleanup/tombstones and bounded customer reads/export are subsequent slices.

Additive migration 0013 protects populated receipt/result/fingerprint history from destructive rollback; empty reversal/reapplication remains required. Twenty new tests cover actual once-only accounting, replay/current authorization, forged/shared/unconfigured signatures, source/payload/namespace/record/token bounds, expiry/multi-source denial, reduced caps, rollback, later-job duplicates, v1 compatibility/deep JSON and three PostgreSQL races (duplicate, conflicting, v1/v2 terminalization).
