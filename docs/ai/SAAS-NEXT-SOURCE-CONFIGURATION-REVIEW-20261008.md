# Native Next source configuration visibility

M7 continuation ports the existing bounded Django source preview into an authenticated Next server page. The API reuses the workspace membership lock and shared internal catalog snapshot; viewer membership permits reading, foreign/revoked/anonymous membership does not. It is read-only and never seeds, enables or executes sources. Existing Django preview remains available.

The response contains workspace identity, at most the first 100 code-ordered entries and an explicit truncation flag. Entries contain code/version, configured enabled/free flags and sanitized capability values only. Rights evidence, controls, provider credentials and budget/financial authority are omitted. Corrupt capability metadata remains null/unknown. Each otherwise valid entry whose ASCII-encoded preview exceeds 1,024 bytes hides its capability values and marks `metadata_limited`; the UI explicitly explains the omission. This bounds valid catalog wire data below the existing 128 KiB Next transport ceiling even for Unicode-heavy metadata. It does not claim metadata completeness or source eligibility.

Next validates the bounded DTO and matching workspace ID before rendering. Ordinary server GET transport forwards only the session cookie; CSRF cookie forwarding remains exclusive to the earlier exact form-context routes. API responses are private/no-store, including denials, with session Vary Cookie. The page distinguishes configuration switches and free-cost declarations from verified availability/rights/cost, explains empty/unknown/truncated metadata and provides no activation controls. React escapes catalog strings; raw HTML, arbitrary URLs and evidence/control references are not rendered.

Engineering review: no database migration/dependency, client fetch bundle, write API or production collection change. Existing snapshot sanitization avoids a duplicate rights evaluator. The metadata byte bound is additive for the API; the existing backend HTML preview retains its behavior. Catalog changes are live configuration snapshots, not immutable run-policy approval. Source eligibility and export rights remain separately enforced at execution/export boundaries.

Verification: local SaaS suite grows to 141 cases (125 passed/16 PostgreSQL-only skipped), including private empty catalog, omitted evidence, Unicode metadata bounds, truncation, viewer/foreign/revoked/anonymous/method checks. Extended real Django–Next HTTP validates empty and configured source pages, XSS escaping, omitted references, viewer reads and foreign denial alongside native draft/cancel/auth flows. Next lint/format/seven transport tests/build/type pass. Final-head PostgreSQL/migration/settings and Web CI remain merge gates. Browser/customer/rights/deployment acceptance stays open.
