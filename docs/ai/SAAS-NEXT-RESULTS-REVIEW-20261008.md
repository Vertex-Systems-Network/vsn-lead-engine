# Current-rights result reads and native Next view

Saved search detail links to a server-rendered Next results page. An exact authenticated transport path reads the new tenant/job-scoped Django GET-only result snapshot. Django rechecks current membership before querying the job or payload; viewers may read, foreign/revoked/anonymous paths cannot disclose payloads. No CSRF cookie, raw source record ref, receipt body/hash/signature, signing identity or fingerprint tokens enter this read DTO. Responses and Next rendering remain private/no-store.

The v2 store accepts only one full batch of at most 25 per job. The read queries at most 26 rows and requires stored row count/job recorded count/acceptance count to agree; the current one-batch view is complete without an arbitrary client page size. Filters, multi-batch pagination and export are deliberately unavailable until their extended contracts exist; unknown query parameters and mutation methods are denied. Current source eligibility/fingerprint, explicit display/storage fields, purpose/retention version, field lineage and per-record deadline are rechecked. Expired, rights-changed, malformed or oversized rows are withheld; no cleanup/accounting mutation follows from a read. Encoded rows are capped at 3072 bytes, total 25, below the existing 128-KiB transport ceiling.

Website values are plain text; no untrusted link or HTML rendering exists. Empty/withheld messaging distinguishes recorded historical totals from currently available records and requested limits from achieved output. No client state/effects, per-row request waterfall, export button or ingestion action is introduced.
