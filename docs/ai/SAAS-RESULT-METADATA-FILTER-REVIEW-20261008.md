# Saved category/source filters and scoped native export

Story: native result GET form → bounded country/category/source query → current-rights snapshot → scoped export preview → explicit CSRF row/field selection → subset-only CSV/once-only receipt. Next remains server-rendered frontend; Django is session/tenant/role/source/retention/usage authority.

## Contract

The saved job has at most twelve categories and twelve explicit source codes. New `category` and `source` query parameters are optional canonical decimal indices 0–11 into those persisted arrays; empty means All. Names, source codes, contact values and signatures do not enter filter URLs. One optional country US/CA/empty can combine with them. Native GET input order is normalized to country/category/source by Next before the exact backend transport allowlist. Repeated, unknown, negative, leading-zero, raw-label, oversized or out-of-job-scope values fail closed. Current membership and scoped job existence remain checked before private metadata is returned; foreign/revoked callers cannot read options. Malformed/oversized saved option metadata returns a generic failure and no rows. No per-request global mutable state or live catalog query controls index mapping.

`category_options` and `source_options` display authorized saved search metadata; they are not claims of live collection permission, provider coverage or available rows. Arrays remain available when payloads expire or source policy is disabled. Completed-job search metadata is immutable through application APIs; ordinal meaning is the persisted job-array order. A future editable search/continuation contract must version these indices rather than silently repurpose them. Current accepted intake remains one complete single-source batch of at most 25; the source control usually has one option. This does not add multi-source acceptance or broader pagination.

Current source/rights/fingerprint, retention, payload and lineage checks run before matching the AND combination of filters. Shown + otherwise available-but-filtered + rights/expiry-withheld stays bounded by 25. All/Clear filters returns the unfiltered authorized snapshot. Filtering and preview write no counter, reservation or CSV. Typed Next guards validate option limits/uniqueness/labels/indices, country/filter echo and matching result rows. Labels and preview summaries render plain escaped text; category/source controls have persistent labels.

Export links and preview back links retain all filters. Preview shows their saved labels and signs exactly the filtered current IDs with existing actor/workspace/job/common-field/short-deadline/key scope. Confirmed selection may only narrow this scope; it cannot add another currently authorized row excluded by the filter. Shared atomic export preparation still rechecks membership/entitlement/caps, current field/source rights/fingerprint and expiry; selected erasure denies replay without an extra charge. The v2 confirmation salt and JSON CSV API remain unchanged. DTO changes are additive for existing API readers; new Next deployment requires the matching backend DTO. No migration, persisted filter token, new raw lead copy, live consumer or production deployment is added.
