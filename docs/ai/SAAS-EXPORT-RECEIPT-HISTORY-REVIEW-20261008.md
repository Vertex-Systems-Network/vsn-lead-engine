# Readonly preparation history and recovery boundary

Story: Results → preparation receipts → signed older-page continuation → redacted receipt metadata. Next is the frontend; Django current membership/role/job scope is authoritative. Each receipt is a preparation accounting record, not a delivery acknowledgement, stored CSV or renewed export permission.

## Contract and privacy review

GET-only `/api/v1/workspaces/<workspace>/jobs/<job>/export-receipts/` returns at most 25 newest-first settled one-unit preparation records plus an optional signed older-page cursor. Owner/admin can read this job's receipts across their workspace; a member can read only their own; viewers are denied. Current membership is checked before query validation and rechecked under the shared workspace lock; scoped job existence precedes continuation decoding. Current role and creator filters apply on every page. Inactive entitlement, exhausted budget, source revocation or payload expiry do not hide historical accounting, but this read cannot grant a download. It queries only workspace/job-matching ledger rows with matching settled one-export-unit reservations.

Returned data is limited to receipt UUID, prepared record count (1–25), one export unit, preparation date, recorded source deadline and whether that deadline has passed. No CSV/contact fields, actor identity, keys, request hashes, keyed digests, selected row IDs, signing evidence or raw source references are returned. This is historical metadata with unchanged pseudonymous retention governance; erasing active lead payloads does not erase/certify anonymity of these receipts. Reads create no counter/reservation, prepare/replay no CSV, settle/refund nothing and never contact providers.

Signed 24-hour cursors bind actor/workspace/job/current visibility scope, timezone-aware creation date and receipt UUID. Strict shape/size/signature/age validation fails closed on malformed, naive, foreign-actor/job, role-scope-changed or expired tokens. Timestamp plus UUID ordering handles ties without offset pagination. Cursor URLs contain only opaque readonly continuation coordinates/signature, no contact payload or write authority; sessions/cursors must remain private and outside analytics. Appending preparations does not freeze an entire multi-page history snapshot. Native First receipt page recovery does not replay an export or incur a charge.

A separate `can_review_receipts` current-role hint keeps the history link available when results expire or source rights change. It is not authority; backend checks remain mandatory. Members are explicitly told this is their own scope, owners/admins job scope. The page explains that preparation does not prove download, no CSV is retained, and a new preview creates a new request that may charge another unit. No download action is offered from history. Current rights and retention still govern any separately reviewed export.

Migration 0016 adds reversible workspace/job/date/UUID and workspace/job/creator/date/UUID lookup indexes, preserving ledger payloads and existing accounting invariants. There is no backfill, data deletion or new stored sensitive field. Production index-build duration/locking requires the existing migration preflight before an actual deployment; no live database migration is performed.

Existing acceptance/export/expiry/role concurrency remains under unchanged shared workspace locking. Backend migration/reversal/reapply/settings checks must pass in exact-head PostgreSQL CI before merge.

Local SaaS: 259 cases, 233 passed and 26 PostgreSQL-only skips; Ruff/format/migration drift/ANPOS pass. Next lint/format, 14 transport tests/build/type and actual HTTP verify private receipt rendering, no-charge reads, viewer link omission, retained receipts after two-row payload erasure and native signed cursor navigation (two genuine preparations with a smaller test-only readonly page limit). Backend separately verifies the production 25-row ceiling. Root regression remains 376 passed/1 skipped/28 subtests, with current required CI recorded after merge.

React review: server page, one bounded fetch, stable receipt UUID keys, escaped typed metadata, UTC date labels, semantic definitions/nav, server-only cookies and no client mutation/waterfall/shared state. The transport forwards only session for receipt reads; exact bounded paths/continuations cannot become write proxies. No browser/visual/responsive/keyboard/WCAG/customer certification is claimed. Live signer/provider/payment/scheduler and deployment remain disabled. Production R2/CLI/Google phone qualification/dedupe/quota facts are unchanged.
