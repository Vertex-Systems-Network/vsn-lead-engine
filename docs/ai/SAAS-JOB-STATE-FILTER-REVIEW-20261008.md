# Saved-job state filter

The native workspace dashboard now filters saved jobs by the server-defined draft/queued/running/partial/completed/failed/paused/cancelled states. This is job state, separate from requested business statuses inside a search. GET filtering creates no jobs, reservations, attempts, receipts or source work.

Django resolves current membership before querying and applies workspace scope, allowed status and UUID continuation in one bounded queryset. Responses remain at most 25 jobs plus one lookahead and are private/no-store. Repeated, unknown, empty/unsupported status and invalid cursor query parameters fail rather than silently changing filter meaning. Existing absent-status and valid cursor requests remain compatible. Unsupported query parameters now return validation errors; unadvertised offset/page parameters are not interpreted as cursor pagination.

Next validates the state and constructs only an exact job-list filter path. Its server GET transport accepts allowed job-state values on that route alone; other API paths cannot inherit arbitrary filter/query destinations. Result workspace and requested status are checked before rendering. Applying a filter starts from the first page; Next and First page links retain the selection. Empty-filter and empty-continuation messages distinguish no matching jobs from no jobs on this page. This is a live view with UUID ordering, not an immutable historical snapshot; manual cursor edits can jump within authorized workspace data but cannot read foreign jobs.

Engineering review: no schema/dependency/mutation/provider change. A small backend query module centralizes validation and pagination previously embedded in the view. Plain GET form/select remains a server component without effects/client fetch state; semantic label/focus and existing palette are preserved. Status enums must stay aligned with the job state contract when future lifecycle changes are introduced.

Verification: local SaaS suite 145 cases (129 passed/16 PostgreSQL-only skipped), four status/query/pagination/tenant/readonly regressions and all earlier native form/source/auth tests. Eight transport tests cover exact filtered path restrictions; Next lint/format/build/type and real HTTP filtered/empty/next/first-page flow pass.
