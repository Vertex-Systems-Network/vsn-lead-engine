# Native Next draft and cancellation screens

M7 continuation implements native Next controls at workspace `search/new` and job `cancel`. Django remains the sole session, membership, form-validation and mutation authority. There is no Next write proxy or client-derived API destination. The existing Django forms remain available and handle invalid submissions with escaped field errors.

- Two exact authenticated GET context routes return bounded workspace identity, a masked CSRF token and a signed user/workspace draft nonce or user/workspace/job/revision cancellation token. They require a valid existing 32-character browser CSRF cookie; no newly seeded backend cookie is silently lost in SSR. An authenticated, read-only `/accounts/check-session/` page seeds missing cookies and offers the fixed dashboard return. Form contexts are private/no-store and Vary Cookie. Viewer/foreign/revoked membership is denied before context issuance.
- Next forwards session plus validated CSRF cookie only on those exact form-context reads; ordinary GET reads remain session-only. Existing origin/path, five-second timeout, 128 KiB response bound, no redirect and no shared cache controls remain. Form navigation disables prefetch, avoiding speculative token issuance. Session/CSRF cookie values do not appear as UI props; only masked CSRF and signed bound form tokens render in hidden controls.
- Native HTML forms post directly to fixed trusted Django action paths. `SAAS_WEB_ORIGIN`, already origin-validated startup configuration, adds exactly that frontend origin to Django CSRF trust. Wildcard hostnames are now rejected before either redirect or CSRF configuration. No wildcard or request-selected trust is added. Production still needs reviewed same-origin proxy/TLS/cookie acceptance; unrelated domains do not acquire shared sessions through configuration.
- Successful mutations return to a fixed configured Next detail path built from server UUIDs. Without frontend configuration, standalone Django redirects remain unchanged. External `next` is not used for mutation destinations. Invalid submissions render existing backend error forms, a deliberate progressive fallback until native error handling is implemented.
- Draft validation retains US/CA, normalized categories, mandatory phone qualification, bounded statuses/fields/source codes/result limit, signed stable retry key and current transactional role recheck. Drafts never reserve or dispatch. Cancellation retains pending-only scope, a ten-minute signed revision token and the existing workspace lock; started/unknown jobs remain protected. Cancellation confirmation displays the server status and revision.

Engineering review: no new database migration/dependency, client bundle, in-process task, source activation or commercial authority. Separate context routes avoid broadening arbitrary API fetches. Roles/capabilities are checked in Django at read and write; frontend visibility never authorizes writes. The only material compatibility change is configured successful form return to Next; unset defaults and backend validation pages are preserved. New semantic fieldsets, labels, help text, number bounds and focus styles received the React checklist; browser keyboard/visual/WCAG assessment remains pending.

Verification: 138 local SaaS cases (122 passed/16 PostgreSQL-only skipped), eight new context/CSRF/role/replay regressions, existing cancellation/source/budget/receipt concurrency tests, seven transport tests, Next lint/format/build/type and real HTTP password-login/native-form flow. HTTP covers wrong Origin, replay/conflicting draft, viewer/foreign denial, stale cancellation after synthetic enqueue, queued release/replay and logout/old-session denial. Required final-head PostgreSQL/migration/settings and Next CI remain merge gates. SQLite is functional HTTP evidence, not row-lock certification.
