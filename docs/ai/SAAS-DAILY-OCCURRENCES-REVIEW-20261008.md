# Internal daily draft occurrences

This slice implements the M3 daily clock/occurrence contract under `apps/saas/`. It does not modify the production collector scheduler. There is no timer, batch scanner, public schedule endpoint, activation endpoint or enqueue/dispatch consumer. New schedules are disabled; activation in tests is synthetic fixture setup. This is schedule persistence and draft materialization, not a running customer scheduler.

- Configuration snapshots normalized US/CA search (phone remains required), IANA zone and local hour/minute. Creation uses a bounded workspace key with exact-payload replay; changed payload conflicts. Configuration editing/revision transitions remain future work.
- A due internal call accepts one local date, bounded to today plus six previous local dates. It records the requested clock, zone, revision, configuration hash, resolved UTC instant/offset and DST interpretation. Existing exact occurrences can replay later without recreating work. Future dates/times and an unbounded backlog fail closed.
- Per M3, an ambiguous time resolves to the earlier UTC instant. A missing time advances to the first valid minute in the same local date. Minute precision is explicit. A removed whole date records `skipped_day` without a job; it cannot silently shift to tomorrow. Half-hour transitions are covered. Existing occurrence resolution is retained on replay if host timezone data later changes; installing/pinning timezone data needs deployment review.
- Workspace lock, current invoking writer membership, originating creator membership and enabled/revision checks guard both initial creation and replay. Foreign workspace lookup is concealed. Revoked/viewer creators cannot continue creating work through a different administrator. The unique schedule/local-date constraint is stronger than the derived schedule/revision/local-date/time job key: revision edits cannot create a second occurrence for that day.
- Draft and occurrence persist atomically. A preexisting job key cannot be adopted by a schedule. No entitlement, capacity reservation or source execution is granted by a draft. The existing enqueue and pre-dispatch gates must still authorize any later execution; an automatic scheduler would need explicit activation, source/entitlement checks, overlap/catch-up policy, retention and operational acceptance first.
- Migration 0011 is additive and empty-history reversible. Populated schedule history blocks destructive reversal and requires a preservation/roll-forward plan.

Review: namespace collision, creator revocation, changed/corrupted configuration, cross-tenant IDs, DST gap/fold/skipped date, transaction failure and old replay are regression cases. Duplicate materialization and creator-role mutation are tested with real PostgreSQL workspace locks in CI. SQLite is local functional evidence only. Customer scheduling and production execution remain open gates.
