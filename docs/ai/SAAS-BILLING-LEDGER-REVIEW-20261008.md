# Disabled internal billing ledger and entitlement deadlines

`core.billing.reconcile_billing` is an internal current-owner/admin service without HTTP ingress, provisioning endpoint, provider call, scheduled task or payment activation. The service switch defaults false; bindings default disabled and the trusted signing registry defaults empty. Only trusted local workspace coordinates determine the binding. Event body claims cannot select issuer/account authority. Bindings with persisted history cannot be reassigned across tenants/issuers or resume from mismatched revision/issuance metadata.

Workspace row locking serializes ordinary billing, reservations, dispatch, exports and entitlement reads. The redacted ledger uniquely binds issuer/event globally and binding/revision locally. New events start at 1 and must advance exactly one revision with nonregressing issuance. Exact-byte replays reverify authority/key/freshness and return the old ledger entry without reapplying limits or deadlines. Cross-workspace uniqueness races roll back the entire losing transaction. Event references, hashes and actor identifiers remain pseudonymous; no raw body/signature/secret/customer/payment details are retained. This is an internal normalized adapter contract, not provider payment truth.

Entitlement stores the signed deadline and trusted binding. `is_current` checks active/deadline/current enabled same-workspace binding. Bound grants require a deadline; existing explicitly provisioned unbound development grants retain null-deadline compatibility. Guards cover reservation/replay, enqueue/replay, pre-dispatch claim/check/start, daily occurrence/replay, candidate/accepted-result ingestion, payload display, export preview/preparation/replay and period advance. Readonly receipt/accounting metadata and destructive expiry cleanup remain accessible subject to their existing roles. Configuration drafts remain editable without activating a provider. Verified past effects still settle after expiry; cancellation may release only previously safe unused capacity.

Billing changes never reset counters, roll periods, release/refund reservations, mint results or change source grants. Lower limits can remain below consumed/reserved usage; new work fails through existing hard-cap checks. The global reconciliation switch governs writes, while binding enablement/deadline govern persisted capability use. Trusted provisioning/revocation must acquire the same workspace lock; direct ORM/admin updates are not a production operator protocol.

Migration 0017 is additive. Empty rollback/reapply is supported; persisted bindings/events or grant deadlines block destructive reversal pending a preservation plan. Local regressions cover rollback injection, tenant/role/key/age/ordering/replay/conflict/downgrade, deadline guards and past-effect settlement. Five PostgreSQL races cover duplicate events, conflicting revisions, issuer-event reuse across tenants, revocation/reservation and revocation/dispatch. Final exact-head CI is required before merge.

Provider-specific raw signature validation, account mapping, actual payment sandbox, authenticated ingress/replay queue, durable recovery/runbook, ledger retention/log redaction, production migrations/backup/encryption, provider/customer/privacy/legal/deployment acceptance and launch remain separate gates. Nothing here seeds a production entitlement or establishes payment truth.
